# OpenMU 数值系统重设计 v1

这是放在独立目录中的**新数值候选系统**。当前 OpenMU 已经提供了独立的 `balance-v1` 启动标记、初始化校验，以及命中率和护甲减伤的运行时分支；本目录仍然不是可以覆盖旧存档的完整发布包。

已有 `..\OpenMU`、`..\MuMain`、数据库、角色、装备和存档不会被本项目的验证脚本修改。本项目不会自动启动游戏服务器、重置数据库或迁移旧存档；正式启用仍需显式选择 `balance-v1` 配置并完成发布门槛。

## 先看什么

1. `docs/数值设计总案.md`：全系统的目标、具体数值、公式及取舍。
2. `artifacts/验证报告.md`：本轮实际跑出来的结果与验证边界。
3. `design/balance.v1.json`：进入可执行模型的成长、职业、伤害、怪物、掉落、金币、药水、强化、活动、组队和 PvP 参数。
4. `design/content-policies.v1.json`：装备、翅膀、宠物、辅助技能、大师节点、任务及特殊内容的细分预算。它们是接入规范，其中未进入仿真的规则会明确标注。
5. `docs/接入清单.md`：真正放进现有游戏前需要完成的接口和验收。

## 这版的方向

以无付费成长的单人 PvE 为主，兼容未来 2–5 人副本；交易和攻城默认不作为已平衡玩法开放。不用反复转生堆无限属性，也不把所有职业变成相同面板。

本轮模型结果：

| 项目 | 结果或设计规则 |
|---|---|
| 普通等级 | 保留 1–400；14 流派的标准模型约 27–36 小时 |
| 大师等级 | 保留 0–200；标准模型约 42–60 小时 |
| 职业 | 7 职业、18 个原引擎职业阶段、每职业两种流派 |
| 属性点 | 每个职业统一每普通等级 5 点；大师不再额外赠送普通属性点 |
| 普通怪 | 成长装备在 400 级的单怪击杀约 4–6 秒；连续刷怪同时计入补给与恢复 |
| Boss | 独立血量、攻击、前摇和奖励预算；不能只加血不加收益 |
| 金币 | 独立于经验倍率；包括出售、药水、维修、传送与可选强化预算 |
| 卓越 | 原始装备表概率 0.35%；80 内容阶以上 250 次有效击杀保底，保底提高后的综合率另算 |
| 强化 | +1 至 +15；失败不降级、不销毁；每档独立失败保底和材料成本 |
| 难度档位 | standard 1×、relaxed 1.5×、journey 0.75×，同时影响普通和大师经验，不改变金币 |

这些耗时是参考装备、固定刷怪方式的**模型估算**，不是实测通关时间，也不包含整个装备收集过程。

## 一键验证

在此目录执行：

```powershell
.\Verify.ps1
```

需要可用的 .NET 10 SDK。完整验证会读取相邻 OpenMU 目录现有的 Release 程序集，在内存中创建一次 S6 配置，导出内容目录；不会连接数据库、保存配置或启动监听端口。

仅运行独立模型、复用已导出的内容目录：

```powershell
.\Verify.ps1 -SkipEngineProbe
```

直接运行规则断言：

```powershell
dotnet run --project src\BalanceLab -- verify design\balance.v1.json artifacts
```

完整脚本以非零退出码报告失败。不要只看“通过数量”，还要看 `acceptance.json`、`content-coverage.json` 和报告中的限制。

## 主要输出

| 文件 | 用途 |
|---|---|
| `xp-tables.json` | 精确普通/大师累计经验表，避免闭式拟合偏差和 ln(0) 边界 |
| `progression.csv` | 各职业流派升级耗时 |
| `combat.json` | 多等级、四档装备的属性、单怪及怪群表现 |
| `economy.json` | 收入、药水、维修、交通、可选强化预算及净余额 |
| `boss-simulation.json` | 每组 64 个固定随机种子的 Boss 样本 |
| `monster-rank-tables.json` | 1–470 内容阶 × 普通/精英/Boss 的完整原型数值 |
| `monster-changes.csv` | 实际地图/怪物编号对应的新数值候选表 |
| `skill-coverage.json` | 每个实际技能的预算和接入状态 |
| `item-coverage.json` | 每个实际物品的预算或药水覆盖规则 |
| `equipment-budgets.json` | 7 职业的装备分槽预算；补偿魔剑缺头盔、格斗缺手套 |
| `upgrade-costs.json` | 强化期望尝试数、保底次数与成本 |
| `pvp-matrix.json` | 14×14 归一化竞技场面板对阵基线，不包含完整控制链实战 |
| `verification.json` | 执行的断言及失败详情 |
| `acceptance.json` | 职业差距、生存等候选方案验收，不表示可直接部署 |
| `run-manifest.json` | 参数哈希、SDK 版本以及原项目关键源文件前后哈希 |

## 不把候选版说成成品

已经完成：可编译运行的新数值内核；14 流派的全等级模型；208 个地图/怪物/难度组合的候选映射；284 个技能和 677 个物品的内容覆盖清单；可重复执行的测试和报告；OpenMU 中 `balance-v1` 的配置互斥/初始化校验、运行时命中率与护甲减伤分支，以及对应回归测试。

仍然没有完成：把候选版的全部公式逐项接进 OpenMU 的伤害、经验、掉落、交易与施法处理链；把其余 267 个技能的类型预算逐个绑定到实际效果/大师节点；全部装备词条和门槛的逐件映射；大师实例、客户端显示、真实地图密度、跨设备云端实测及存档迁移。

因此，本目录能运行的是**数值设计与验证工具**。不能把 JSON 复制进原项目就认为游戏已经生效，也不能用本轮断言替代服务端集成测试和实际试玩。
