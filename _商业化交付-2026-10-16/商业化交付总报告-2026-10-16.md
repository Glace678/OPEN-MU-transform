本轮对全仓库自有源码做了“行为保持”的工程化整理，目标是**可读、可维护、可商业化**，且不引入玩法回归。所有改动均在独立 git 分支上小步提交，并以“构建 + 测试全绿”作为验收闸。

| 维度 | 结果 |
|---|---|
| C# 服务端（OpenMU，.NET 10） | 构建 **0 错误**；测试 **2164 通过 / 0 失败 / 6 跳过**（10 个测试程序集） |
| C++ 客户端（MuMain，C++20/SDL3，Release x64） | 干净全量重建 **0 错误**；ctest **246/246 全部通过** |
| 自有源码格式化 | **1062 个** C/C++ 自有文件全部到达 clang-format 幂等不动点，经“词法 token + 非 ASCII 字节”双门控校验，**零行为改动** |

| 高风险缺陷告警 | **全部清零**（C4701/C4703/C4312/C4477/C4554/C4706/C5205/C4099/C4996/C4244/C4389），其中修复 **3 个真实逻辑 bug** 与 1 处未定义行为（多态基类非虚析构） |

**重要说明（诚实边界）**：游戏客户端的核心战斗/网络/背包逻辑中，剩余 324 条 C++ 有符号/无符号与未用变量告警属于 /W4 行为相关级别。它们的“修正”（改类型、加转换、删变量）可能改变 mana 判定、伤害循环边界、随机数序列等玩法语义，且本机无法通过完整游戏对局回归验证。因此本轮**没有机械地把它们清零**，而是保留为带文件:行号与修复建议的精确 backlog——这是“无 bug”优先于“告警数字好看”的工程取舍。纯样式的 shadowing 告警（851 条）已在构建策略中以注释形式显式降级，理由见 §4.4。

## 4. 已完成的整理（方法与证据）

### 4.1 安全依赖升级（C# 服务端）

- **SixLabors.ImageSharp → 4.1.3**：修复 5 个 GHSA（ICC CLUT、Histogram、T4、T6、BigTIFF 越界）。
- **SixLabors.ImageSharp.Drawing 1.0.0**：全仓库零引用，已删除。
- **System.Security.Cryptography.Xml 8.0.4 → 10.0.13**，并钉版 `Pkcs` 10.0.13。
- 适配 ImageSharp 4.x 破坏性 API：两份 `GameMapTerrainExtensions.cs` 改用 `new Rgba32(...)` 替代 `Color.FromRgb/Black/Gray`。
- 中央包管理：`OpenMU/src/Directory.Packages.props` 统一版本。

### 4.2 全量确定性格式化（行为保持，核心工作量）

- 规则（`MuMain/.clang-format`）：4 空格、Allman 大括号（命名空间后换行）、列宽 120、指针左对齐、`#include` 不排序、预处理指令不缩进、字符串不折断。
- 范围：`src/source`、`src/MuEditor`、`tests` 下全部自有文件；`ThirdParty` 与 `third_party` 与 `out/` 排除。
- **行为保持双门控**：
  1. 合并反斜杠续行后、去除所有空白字符的 **token 字节序列必须相等**（保证只是空白/换行/括号风格变化，不改变任何 token）；
  2. **非 ASCII 字节 run 必须相等**（保护韩文/中文注释与字符串字面量，不被破坏）。
- 权威方法：`clang-format --style=file <真实路径>`（clang-format 从文件目录读取项目 `.clang-format`，单遍即幂等，无 BOM）。
- 最终结果：**1062 个 in-scope 文件 0 个未格式化**（`coverage_check.py` 复核）。
- 过程中曾发现“临时文件法（加 BOM）对部分文件输出与真实路径不一致”，已改用真实路径法并纠正；此前被误写的 226 个文件已用 `git checkout` 还原后重新权威格式化。
- 两个 iOS/macOS 的 `.mm`（ObjC++）真实路径已是 0 replacement，无需格式化，已还原。

### 4.3 高风险缺陷修复（含真实 bug，提交 `57253ce6` / `ff65f6df` / `6a28c038`）

**真实逻辑 bug（3 个）：**

1. `ZzzEffect.cpp:813`：`if (o->SubType = 0)` 是**赋值**而非比较——既把 `SubType` 置 0 又使分支恒假。改为 `== 0`。
2. `MoveHandlers.cpp:9977`：`< 8 & rand_fps_check(1)` 误用单 `&`（按位且额外多抽一次随机数）。改为 `&&`。
3. `ZzzInfomation.cpp:414/419`：`%8d` 对应 `int64_t ItemValue`，在 64 位下截断。改为 `%8lld`。

**未定义行为（1 处）：**

- `IConnecter.h`：多态基类析构非虚，经由基类指针 `delete` 是 UB（C5205）。新增 `virtual ~IConnecter()`。

**未初始化变量（编译器无法证明全路径赋值，已全部给确定性初值）：**

- `ZzzAI`：cx/cy；
- `ZzzInventory`：大天使武器 iMana/iWeaponSpeed/iNeedStrength/iNeedDex、`tm* ExpireTime=nullptr`；
- `WSclient`：三处 fruit 索引；
- `MoveHandlers`：iBone01/iBone02/iBlurIdentity/iTypeBlur；
- `ZzzEffectJoint`：Distance 初值 `1.0e30f`（SubType==7 分支不赋值，初值 >35 保证不误杀）；
- `ZzzEffect`：Height/Scale；`ZzzEffectParticle`：fScale/fLight；
- `UIMng` docking：i/j/nXCoord/nYCoord、pWin；
- `NewUICharacterInfoWindow`：iAddPoint/iMinusPoint。

**转换/类型：**

- `ZzzObject.cpp:5334` 哨兵指针改为 `(OBJECT*)(uintptr_t)0xdddddddd`（C4312，整数→指针）。
- `Event.h`：`struct BMD;` 与 `class BMD`（`ZzzBMD.h`）冲突，统一为 `class BMD;`（C4099）。
- `LocalLoginCredentials.cpp`：5 处 `std::getenv`（C4996）替换为可移植 `GetEnvVar`（Windows 走 `getenv_s`，其它平台走 `std::getenv`），启动期单线程语义不变。
- `GamepadMapper.cpp:129/130`：dpad 差量 int→float 显式 `static_cast<float>`（C4244）。
- `NewUIMasterLevel.cpp:1025`：技能品牌枚举（int）与 `BYTE` 比较显式转换（C4389），数值语义不变。

## 6. 已知遗留（精确 backlog，非缺陷）

### 6.1 C++ 剩余 324 条 /W4 告警（逐条 CSV）

文件：`cpp-warning-backlog.csv`（本目录，UTF-8 BOM，Excel 可直接打开）。每条含 `code / file / line / category / message / recommended_fix`。

| 告警码 | 数量 | 含义 | 模块分布（前三） | 处置建议 |
|---|---:|---|---|---|
| C4245 | 178 | 有符号/无符号转换 | World(102)、Engine(78)、GameLogic(42) | 证明不会为负后统一类型或显式 `static_cast`；先处理哨兵（-1） |
| C4189 | 115 | 局部变量未使用 | Network(33)、UI(41)、GameLogic | 确认初值无副作用（`rand()` 消耗 RNG、getter 可能有副作用）再删除；纯常量可删 |

**为什么没有本轮直接改**：这些集中在战斗技能（mana 判定）、技能目标循环、封包长度循环、背包数值等最脆弱代码。改类型/转换可能改变：负数分支（如 -1 哨兵）、循环边界（off-by-one）、随机数序列（删除一次 `rand()` 调用）。在没有完整对局回归的情况下，机械清零会制造**不可见的玩法回归**，违背“无 bug”目标。建议按 backlog 顺序，在可进行游戏内对局验证的环境中分批修复（每批一个模块 + 对局验证）。
