# Localization.Tests 说明（第二轮清零补修）

本工程是本地化回归控制台（`dotnet run`）。任何 `throw` 即该用例失败；全绿返回 0。

## 已登记的豁免（exemption）

### OnePercentLow（纯文本直渲标签，豁免占位符比对）
- key：`Game.OnePercentLow`，英文基线值形如 `1% Low`。
- 该串是**直接渲染的遥测标签**，不经过 `printf` 格式化；其中的 `1%` 是字面百分号，不是占位符。
- 若按普通占位符规则比对，会把 `1%` 误判为残缺格式串。因此它在
  `LocalizationFormatClassification.PlainTextKeys` 中登记为纯文本，
  `LocalizationCoverageReporter` 跳过其占位符比对，且**不算作错误**。
- 用例锁定：
  - `Program.cs / PlainTextLabel`：es 译文 `1 % bajo` 不产生 error、不产生 placeholder mismatch。
  - `Program.cs / RepositoryMatrix`：真实仓库 `PlainTextClassifications.Count == 1`（即仅此一条）。
  - `RepairedPrintfResourceTests / LiteralLabels`：de/es/id/pl/pt/ru/tl/uk/zh-TW 的
    `OnePercentLow` 译文必须保持字面标签，不得新增 printf 参数或转义百分号。
- **新增语种时请勿复制此豁免**：仅 `Game.OnePercentLow` 一条；其他 `%` 标签不享受。

## 本轮新增硬失败（hard fail，error 级，会让 CI 失败）

在 `LocalizationTextChecks.IsMojibakeHardFail(value)` 中实现，
由 `LocalizationCoverageReporter.AuditTextWarnings` 对**译文 value** 触发 issue
`mojibake_residue`，严重度 = `ErrorSeverity`（即计入 ErrorCount、退出码 1）。命中三种之一：

1. **U+FFFD 替换字符**；
2. **连续 4 个及以上问号** `????`（旧规则是 5 个，本轮收紧到 4 个）；
3. **连续 >=4 个 Latin-1 补充区字符（U+0080-U+00FF）且其中至少含一个 Latin-1 符号位**
   （U+00A0-U+00BF、乘号 U+00D7、除号 U+00F7）——这是韩文 cp949/cp1252 乱码块残留的特征
   （如 `¼ºÁÖÀÇ Ç¥½Ä`）。

### 防误报（必须满足）
- de/es/pt 等合法重音字符 a-umlaut/o-umlaut/u-umlaut/a-tilde/c-cedilla/a-acute/e-acute/e-grave、
  大写串 `AeOeUe-ss`、葡语 `acao` 等要么是孤立字母，要么是不含 Latin-1 符号位的纯字母串，
  **不触发**硬失败。
- 用例 `AccentedText` / `AccentedEuropeanText` 锁定该行为（ErrorCount=0、WarningCount=0）。

### 范围说明（为什么 key 不参与硬失败）
- BUG-49 的 EUC-KR 乱码 **key**（约 252 个 name 属性，跨全部语种）按约束**不得改 key**，
  属已登记的遗留项。因此硬失败只作用于**译文 value**；key 层面仍只对半角假名发 warning。
- 半角假名（U+FF65-U+FF9F）保留为 warning（`suspect_legacy_text`），**不**升级为硬失败。
